# Frontend — Design & Architecture Guide

> Source of truth for this React + Vite frontend. Read before adding pages, components, or data-fetching code.

## Tech Stack

| Area | Technology |
|---|---|
| Framework | React 19 + Vite |
| Language | TypeScript (strict) |
| Routing | `react-router` v7 |
| Styling | Tailwind CSS (+ shadcn/ui, if selected) |
| Data fetching | `@tanstack/react-query` v5 |
| HTTP client | `axios` (single shared instance in `src/lib/axios/http.ts`) |
| Auth | Better Auth (session cookie shared with the backend), if selected |

## Architectural Doctrine: Feature-First, Layered by Scope

- `pages/` contains **route-level components only** — composition and layout. No direct HTTP calls, no business logic.
- Domain logic lives in `features/<feature>/` capsules (created as modules are added, e.g. auth). Each feature owns its own components, queries, and types.
- Shared, non-domain-specific code lives in `components/` and `lib/`.

## Directory Structure

```
src/
├── main.tsx               ← App entry (providers, router mount)
├── router.tsx             ← Route table
├── pages/                 ← Route-level components (composition only)
├── components/
│   ├── ui/                  ← shadcn/ui primitives only — never feature-aware
│   ├── providers/            ← QueryClientProvider, ThemeProvider, etc.
│   ├── layout.tsx             ← App shell layout
│   └── error-boundary.tsx     ← Top-level error boundary
├── features/               ← One capsule per domain feature (added by modules, e.g. `features/auth/`)
│   └── <feature>/
│       ├── components/         ← Feature-specific UI
│       ├── queries/             ← TanStack Query hooks (`*.query.ts`, `*.mutations.ts`)
│       └── types/                ← Feature-specific types/schemas
├── lib/
│   ├── axios/http.ts        ← Single shared HTTP client instance
│   └── utils.ts              ← `cn()` and small shared helpers
└── types/                  ← Global shared types
```

## Component Organization Rules

| Scope | Location | Allowed to depend on |
|---|---|---|
| UI primitives | `components/ui` | `lib/utils` only |
| Global reusable UI | `components/` (root) | `components/ui`, `lib/*` (never `features/*`) |
| Feature UI | `features/<feature>/components` | `components/ui`, `lib/*`, its own feature's queries/types |

## Data Fetching Conventions

- All HTTP calls go through the shared `api` instance in `lib/axios/http.ts`. Never instantiate a second axios client.
- Reads/writes are wrapped in TanStack Query hooks colocated with their feature (`features/<feature>/queries/<feature>.query.ts`, `*.mutations.ts`), not called ad-hoc inside components.
- Query keys are defined once per feature and exported for reuse.

## Conventions

- `components/ui` is regenerated by `shadcn` — do not hand-edit generated primitives beyond what the CLI produces.
- Keep `pages/` thin: fetch/mutate through feature queries, render through feature/shared components.
- Environment variables consumed by the client **must** be prefixed `VITE_`.
